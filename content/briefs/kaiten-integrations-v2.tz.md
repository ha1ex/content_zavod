# ТЗ на лендинг — kaiten-integrations-v2

> Сгенерировано фабрикой ТЗ (Контент-завод Кайтен) из сырых данных. Документ для ревью командой; машинный бриф — `content/briefs/kaiten-integrations-v2.json`.

## Summary

Обновление лендинга «Интеграции» Кайтена (/features/integrations/). Текущая страница kaiten.ru перечисляет девять интеграций и открытый API и отстала от продукта: в базе знаний (раздел «Интеграции, API, Дополнения») уже 16 интеграций в четырех группах, дополнения в карточках, External Webhooks, SCIM, лимит API 50 запросов в секунду и услуга «Настройка интеграций». Режим custom: состав блоков и тексты зафиксированы в этом ТЗ, тексты собраны по статьям базы знаний. Логика страницы: первый экран — Кайтен связывается с сервисами команды, а если готового решения нет, можно собрать свое → готовые интеграции без программирования по четырем группам → дополнения прямо в карточке → API и вебхуки для своих систем → услуга настройки интеграций командой Кайтен → финальный призыв зарегистрироваться. Визуалы — мокапы контент-завода (домен PM).

## Аудитория

- **Основная:** Команды, которые работают сразу в нескольких сервисах — мессенджерах, почте, репозиториях, формах сайта, CRM и телефонии — и хотят, чтобы задачи и события из них попадали в Кайтен без ручного переноса
- **Принимает решение:** Руководитель команды или отдела и ИТ-руководитель — решают, какие сервисы связать с Кайтеном, хватит ли готовых интеграций или нужна своя через API
- **Роли:** Тимлиды и руководители разработки, которые связывают ветки, коммиты и пулл-реквесты с карточками, Руководители проектов и отделов, которым нужны уведомления о задачах в привычном мессенджере, Маркетологи, продажи и поддержка, которые принимают заявки с сайта, из форм, почты и звонков, Разработчики и администраторы, которые настраивают вебхуки, API, SCIM и собственные дополнения

**Боли:**
- Уведомления о задачах теряются в отдельной вкладке — боты в Telegram, Макс, Slack и Пачке присылают их в рабочую переписку
- Заявки с сайта, из форм и писем переносятся в трекер руками — вебхуки, Tilda, Google Forms и почта создают карточки сами
- Контекст разработки живет в репозитории — GitHub и GitLab показывают ветки, коммиты и merge request прямо в карточке
- Файлы, документы и звонки разбросаны по сервисам — дополнения Google Docs, Яндекс Диск и Sipuni встраивают их в карточку
- Готовой интеграции нет, а своих рук на настройку не хватает — есть API, вебхуки, no-code платформы и услуга настройки от команды Кайтен

**Критерии выбора:**
- Готовые интеграции с мессенджерами, почтой, календарем, формами и сервисами разработки без программирования
- Российские мессенджеры и сервисы: Макс, Пачка, Яндекс Диск, Albato, MoreKIT, ТестОпс
- Открытый API с достаточным лимитом запросов и вебхуки в обе стороны
- Работа интеграций и дополнений в серверной версии
- Возможность заказать настройку интеграции, если нет своих ресурсов

**Возражения:**
- Потребуется программист — готовые интеграции настраиваются в пространстве или профиле без кода
- Нашего мессенджера нет — кроме Telegram и Slack есть Макс и Пачка
- У нас серверная версия — интеграции с GitLab и GitHub работают на серверных установках, дополнения подключаются модулем «Дополнения»
- Некому настраивать — команда Кайтен или партнеры настроят интеграцию с CRM, Helpdesk, 1С, BI, почтой и мессенджерами

### tabbed_feature — готовые интеграции
**Готовые интеграции без программирования**

Заголовок: Готовые интеграции без программирования
Подзаголовок: Настраиваются в пространстве или профиле за несколько минут
Вкладка 1. Мессенджеры и почта — Задачи в рабочей переписке
— Telegram и Макс: личные уведомления, новые карточки и комментарии к задачам прямо в чате с ботом
— Макс: ответы на заявки Службы поддержки без перехода в Кайтен
— Slack: события пространства в канале, карточки из сообщений и статус по срокам и блокировкам
— Пачка: уведомления о событиях пространства в чат команды или руководителя
— Электронная почта: письмо на специальный адрес становится карточкой вместе с вложениями
Вкладка 2. Календарь и сайты — Сроки и заявки там, где они появляются
— Календарь: сроки ваших задач или всего пространства в Google, Outlook и других календарях
— Tilda: заявка с формы сайта попадает карточкой на выбранную доску
— Google Forms: ответы формы создают карточки через вебхук
Вкладка 3. No-code платформы — Сценарии «событие — действие» между сервисами
— Albato и MoreKIT: российские сервисы для связки Кайтена с CRM, почтой и другими приложениями
— Zapier: синхронизация Кайтена с приложениями из каталога Zapier
— Пример: сделка в amoCRM создает задачу в Кайтене через MoreKIT
Вкладка 4. Разработка и тестирование — Контекст разработки рядом с задачей
— GitHub и GitLab: коммиты в комментариях к карточке, карточка сама переезжает при создании ветки, пулл-реквесте, ревью и слиянии
— ТестОпс: тест-кейсы, запуски и дефекты связаны с задачами, задачу можно создать из открытого дефекта
— WebStorm: задачи Кайтена в списке задач IDE
— Confluence: статус карточки на странице документа

### media_copy — дополнения
**Дополнения прямо в карточке**

Заголовок: Дополнения прямо в карточке
Описание: Дополнения добавляют в карточку кнопки, блоки с данными и значки на фасаде. Включаются для пространства в один клик
Пункты:
— GitLab и GitHub: ветки, коммиты, merge request и issue отдельными блоками в карточке, в том числе для self-managed GitLab
— Google Docs: документы, таблицы и презентации создаются и редактируются, не выходя из Кайтена
— Яндекс Диск: файлы с Диска прикрепляются к задаче
— Sipuni: звонки из карточки, история и записи разговоров рядом с задачей
— Свое дополнение: разработайте сами или закажите разработку
Сноска: В облачной версии дополнения доступны по умолчанию, в серверной — с модулем «Дополнения»

Пункты:

— Webhooks: внешние системы создают карточки по заранее созданному адресу

— SCIM: пользователи синхронизируются с вашим identity provider

- Нужно ли упоминать MCP-сервер и Kaiten CLI (у завода есть лендинги kaiten-mcp и kaiten-cli) — в разделе интеграций базы знаний их нет
